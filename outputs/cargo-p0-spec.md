# Планировщик загрузки P0

Техническое задание и этапы разработки. Согласованная основа P0 с несколькими опорами, редакция 2, 15 ноября 2026 года. Реализация ещё не начата.

Приложение помогает частному пользователю или малому бизнесу разместить коробки в машине с учётом обязательных грузов, допустимых положений, массы и порядка выгрузки. Результат — проверенная схема и пошаговая 3D-инструкция. Основной демонстрационный сценарий: загрузить таблицу, выбрать машину, получить раскладку, пройти выгрузку на трёх остановках прямо на телефоне.

# Согласованные требования и решения

Пользователь подтвердил P0 и формат PWA с установкой с сайта. Подтверждены прямоугольная геометрия, импорт Excel, выбор разрешённых опорных граней на 3D-коробке, настройка максимальной массы сверху, обязательность грузов галочками и инструкции в 3D. Остальные ранее перечисленные функции P0 сохраняются.

Пользователь согласовал основу P0 и замену ограничения одной опоры на несколько опор с почти полным покрытием дна и приближённым распределением нагрузки по площади контакта. Численные допуски опоры ниже — начальные инженерные параметры реализации; это не норматив прочности упаковки.

Рассмотрены три подхода:

| Подход | Выгода | Цена |
| --- | --- | --- |
| PWA с локальным расчётом | Один продукт для телефона и компьютера; офлайн; данные расчёта остаются на устройстве | Производительность зависит от телефона |
| PWA с серверным расчётом | Единое вычислительное окружение; проще обслуживать большие задачи | Интернет, серверные ресурсы и очередь задач |
| Отдельное мобильное приложение | Публикация в магазинах и дополнительные возможности платформы | Сборки, публикация и отдельная проверка мобильных платформ |

Выбран пользователем формат PWA. Архитектура — локальный расчёт и небольшой сервер только для ссылок на результаты. Основное приложение работает без сервера обмена.

# Границы P0

Одна машина, один рейс, загрузка всех вещей в начале маршрута, последовательная выгрузка на заданных остановках. Маршрут задаётся номерами: приложение не строит дороги и не меняет порядок адресов. Все предметы — жёсткие прямоугольные параллелепипеды, расположенные параллельно осям кузова.

В P0 входят каталог машин, ручной ввод, импорт таблиц, расчёт, редактирование раскладки, 3D-просмотр, инструкции, локальное сохранение, файл проекта, PDF и ссылка для просмотра. Полный сценарий доступен на телефоне без регистрации.

За рамками P0: несколько машин, подбор оптимального автопарка, промежуточный забор груза, произвольная геометрия мебели, легковые багажники сложной формы, колёсные арки как отдельные препятствия, боковая загрузка, нагрузки на оси, крепления и динамика при движении, аккаунты, совместное редактирование, AI-ввод и публикация в магазинах.

# Машина и система координат

Кузов задаётся полезными внутренними длиной, шириной, высотой и допустимой массой груза. Размеры не внешние и не полученные из рекламного объёма в кубометрах.

Начало координат находится на полу у заднего проёма слева при взгляде внутрь. X направлен в глубину машины, Y вправо, Z вверх. Проём находится при X = 0. В P0 проём совпадает с поперечным сечением используемого прямоугольного объёма. Это явное упрощение: если реальный проём уже или ниже, пользователь задаёт меньший полезный прямоугольник. Приложение не обещает проверить настоящий дверной проём по одному названию машины.

Каталог стартует с 5–10 проверенных модификаций подходящих фургонов или прямоугольных кузовов. У записи есть модель, модификация, размеры, источник и дата проверки. Для сложного кузова указывается именно консервативный полезный прямоугольник и объясняется потеря объёма. Непроверенные модели не добавляются ради количества. Любой параметр можно изменить; пользователь подтверждает размеры и грузоподъёмность конкретной машины. Всегда доступна «Своя машина».

В интерфейсе по умолчанию сантиметры и килограммы, с переключением мм/см/м. В расчёте — целые миллиметры и граммы. Значения с более мелкой точностью не округляются скрытно: пользователь видит преобразование и подтверждает его.

Зазоры по умолчанию: от боковых стен, передней и задней границы и потолка — 10 мм; между соседними коробками по горизонтали — 5 мм. На полу и между опорными поверхностями вертикальный зазор равен нулю. Все зазоры доступны в дополнительных настройках и могут быть нулевыми. Межкоробочный зазор применяется к коробкам с пересекающимися по высоте внутренностями; он не мешает непосредственному контакту верхней и нижней коробок.

# Ввод грузов

Одна строка описывает тип одинаковых коробок. Поля:

| Поле | Поведение |
| --- | --- |
| Название | Обязательно; приложение предлагает редактируемое «Коробка 1» |
| Длина, ширина, высота | Положительные размеры одной коробки |
| Количество | Целое число от 1 |
| Масса | Положительная масса одной коробки; неизвестное значение не заменяется нулём |
| Остановка выгрузки | Целое положительное число; по умолчанию 1 |
| Обязательный груз | По умолчанию включено; действует на всё количество в строке |
| Разрешённые опорные грани | По умолчанию все шесть |
| Допустимая масса сверху | По умолчанию «Без ограничения»; либо число от 0 кг |

Есть добавление, копирование, удаление, массовое выделение и переключение обязательности. Для частичной обязательности пользователь разделяет строку на две, например 7 обязательных и 3 необязательных. В расчёте каждый экземпляр имеет устойчивый уникальный ID, например A-001; ID сохраняется при пересчёте неизменённых экземпляров.

Выбор положения: вращаемая 3D-коробка с шестью пронумерованными гранями. Нажатие разрешает или запрещает ставить коробку на эту физическую грань. Подпись объясняет: «Выбранные грани могут оказаться снизу». Дублирующий список шести граней обеспечивает доступность и удобство на маленьком экране. Запретить все грани нельзя. Направление исходных размеров и метки граней видны в редакторе и инструкции.

Вращение вокруг вертикали допускается на 0, 90, 180, 270 градусов. Произвольные диагональные повороты не входят в P0. Внутри модели сохраняются до 24 пространственных ориентаций с идентичностью граней; геометрически совпадающие состояния можно объединять только когда это не теряет различия разрешённых граней и отображаемых меток.

# Импорт таблиц

Поддерживаются XLSX, XLS и CSV. Есть скачиваемый шаблон XLSX. Импорт происходит на устройстве и не отправляет исходную таблицу на сервер.

Порядок: выбрать файл и лист → выбрать строку заголовков → сопоставить колонки → указать единицы → увидеть предпросмотр и ошибки → добавить строки в проект. Исходный проект меняется только после подтверждения. По умолчанию импорт добавляет данные; замена списка — отдельное явное действие.

Обязательные колонки: размеры, количество и масса. Название можно сгенерировать. Для отсутствующих необязательных колонок используются видимые значения по умолчанию. Поддерживаются десятичная запятая, разделители CSV «;», «,» и табуляция; неоднозначные значения требуют выбора пользователя. Кодировка CSV — UTF-8, с возможностью выбрать Windows-1251.

Дополнительные колонки: остановка, обязательность, максимум массы сверху и разрешённые грани в формате шаблона. Для каждой ошибки показываются лист, строка, поле и причина. Исправить можно до импорта. Импорт только корректных строк разрешён отдельным действием с явным числом пропущенных строк.

Макросы и формулы не исполняются. Формульные ячейки обязательных числовых полей помечаются ошибкой: предлагается вставить значения. Это исключает использование устаревшего кеша формул как достоверных размеров.

Пределы P0: файл 10 МиБ, 1000 непустых строк на предпросмотр; в расчёте не более 100 типов и 300 отдельных коробок. Ограничения проверяются до разворачивания количества. Разбор выполняется в worker с возможностью прервать; чрезмерно большие листы/распакованные данные отклоняются с понятным сообщением.

# Опора и масса сверху

Модель P0: коробка стоит на полу либо опирается на одну или несколько нижних коробок. Все участвующие верхние грани лежат точно на высоте дна верхней коробки. Контактом считается пересечение прямоугольников с положительной площадью; касание ребром не передаёт нагрузку. Одна большая коробка может стоять на нескольких маленьких, а на одной большой могут стоять несколько маленьких. Полная опора одним предметом не требуется.

Почти полная опора определяется тремя одновременными условиями: фактическая объединённая площадь контакта составляет не менее 95% площади дна; все четыре угла дна входят в фактическую область опоры; каждый участок дна находится не дальше g/2 от фактической опоры по метрике L∞, где g = min(горизонтальный зазор проекта, 5 мм). Последнее проверяется покрытием дна объединением контактных прямоугольников, расширенных на g/2 по X и Y. Это разрешает узкие швы, но не широкие провалы или внешние свесы. При g = 0 требуется 100% фактического покрытия. Расширенные области используются только для проверки щелей: они не становятся контактами и не получают нагрузку. Числа 95% и 5 мм — версионируемые параметры модели support-v1, без отдельной настройки процента пользователем в P0.

«Без ограничения» отключает проверку прочности конкретной коробки, но не проверку наличия опоры. Число 0 означает, что ставить сверху ничего нельзя. Число 20 кг означает максимальную суммарную долю нагрузки, переданную этой коробке со всех верхних уровней, а не массу только непосредственного соседа сверху. Собственная масса в этот лимит не входит.

Опоры образуют направленный ациклический граф сверху вниз. Для коробки i с собственной массой mᵢ и входящей нагрузкой Lᵢ на опору j передаётся (mᵢ + Lᵢ) × Aᵢⱼ / ΣAᵢₖ, где A — фактические площади контакта. Входящие доли суммируются у получателей; обработка идёт сверху вниз. Одна и та же масса не должна повторно целиком учитываться на каждой опоре. Сумма реакций пола равна суммарной массе размещённых грузов. Внутри расчёта доли грамма сохраняются; округление для отображения не меняет проверяемую нагрузку. При добавлении или перемещении коробки пересчитывается граф затронутой укладки. Ограничение одно для всех разрешённых положений коробки; прочность отдельных граней в P0 не задаётся.

Распределение по площади — приближённая модель с равномерным давлением под каждой коробкой; она не решает уравнения моментов и не учитывает смещённый центр массы содержимого, жёсткость и деформацию упаковки. Поэтому результат обозначается как проверка геометрии и расчётной нагрузки по принятой модели, а не гарантия физической устойчивости. Крепления и динамика движения также вне P0. [Пример подхода с распределением по площади](https://www.mdpi.com/2227-7390/13/10/1668).

# Порядок выгрузки и 3D-инструкция

Номер 1 означает первую выгрузку. Коробка ранней остановки должна извлекаться без снятия грузов следующих остановок. Внутри одной остановки приложение выбирает порядок само.

Проверяемый путь в P0 — прямое перемещение коробки вдоль X к заднему проёму в её конечной ориентации и на её текущей высоте. Перехваты, наклоны и обход других коробок не моделируются. Показанный путь является геометрической проверкой, а не моделированием рук грузчика или подъёмной техники.

Строится граф обязательного порядка извлечения. Если коробка A перекрывает прямой путь B, A нужно убрать раньше B. Если A имеет контакт с B, A также нужно убрать раньше B; при нескольких опорах добавляется ребро к каждой. В P0 не пытаемся вынимать отдельную опору из-под оставленного груза, даже если оставшихся опор могло бы хватить. Для каждого ребра A → B остановка A должна быть не позже остановки B. Циклы означают непригодную раскладку в принятой модели. Внутри одинаковой остановки используется детерминированный топологический порядок.

Валидатор дополнительно проигрывает выгрузку по одной коробке: на каждом шаге путь свободен, остаток груза имеет опору и не превышает лимиты нагрузки. Загрузка получается обращением проверенной полной последовательности выгрузки и тоже проверяется пошагово. Только после этого доступны готовые инструкции.

В 3D-инструкции есть режимы «Загрузить» и «Выгрузить», выбор остановки, текущий шаг, анимация движения выбранной коробки, её ID, масса, ориентация, кнопки назад/дальше и отметка выполнения. Сцена показывает фактический состав кузова на этом шаге. Можно поставить анимацию на паузу, изменить скорость и угол камеры. Прогресс сохраняется локально и относится к конкретной версии раскладки; изменение плана его сбрасывает с объяснением.

# Алгоритм и смысл результата

Задача — ограниченная трёхмерная упаковка в один кузов с обязательным подмножеством, нагрузкой сверху и доступностью выгрузки. Основной подход — конструктивная эвристика на перспективных точках размещения, несколько стартовых порядков и ограниченный локальный поиск. Это собственная реализация ограниченной модели; научная база метода — [Extreme Point-Based Heuristics for Three-Dimensional Bin Packing](https://pubsonline.informs.org/doi/abs/10.1287/ijoc.1070.0250).

Этапы расчёта:

1. Нормализовать и проверить данные, сгенерировать разрешённые ориентации. Проверить необходимые условия: отдельные габариты, суммарную массу обязательных грузов и их суммарный физический объём. Эти условия могут доказать отдельные причины невозможности, но не доказывают существование раскладки.
2. Построить несколько раскладок, меняя порядок коробок по остановкам, ограничениям, объёму, площади основания и массе. Последние остановки обычно располагаются глубже, но остановкам не выделяются жёсткие изолированные зоны.
3. Проверять кандидатов у пола, стен и границ уже размещённых коробок, включая допустимые позиции на опорах. Проверять геометрию, зазоры, ориентацию, массу, поддержку и зависимости выгрузки при добавлении.
4. Улучшать результат переупаковкой небольших групп, заменой ориентаций и изменением порядка. Обязательность учитывается в цели; это не правило «всегда физически размещать обязательные первыми», поскольку необязательная коробка может быть полезной опорой.
5. Независимым валидатором проверить лучший результат и все шаги инструкций. Валидатор вычисляет факты из координат и ориентаций заново, не доверяя флагам допустимости из эвристики.

Порядок целей: сначала разместить все обязательные экземпляры; затем максимизировать суммарный физический объём необязательных размещённых коробок; при равенстве уменьшать высоту укладки и затем использовать детерминированное разрешение равенства. Выбор объёма, а не количества, — предлагаемый критерий P0; отдельные цели оптимизации будут позже.

В интерфейсе нет обещания математически оптимальной раскладки. Результат называется «Лучший найденный вариант». Плотность — физический объём коробок относительно введённого полезного объёма кузова; масса и количество показываются отдельно.

Статусы: готовый допустимый план; частичный результат с отсутствующими обязательными экземплярами; доказанное нарушение необходимого условия; допустимый план не найден за выделенное время; расчёт отменён; ошибка расчёта. Если обязательные вещи не вошли, частичная схема не получает статус готовой инструкции. Пользователь может изменить обязательность и пересчитать. При отмене сохраняется лучший уже проверенный результат, если он есть.

Для каждого неразмещённого экземпляра различаются доказанная причина («не проходит ни в одной разрешённой ориентации») и отсутствие найденного размещения. Неудача эвристики не выдаётся за доказательство невозможности.

Бюджет быстрого расчёта по умолчанию 5 секунд; пользователь может продолжить поиск до 30 секунд. Это лимиты вычисления, а не обещание найти решение. Worker регулярно отдаёт текущий лучший вариант и умеет отменяться. Воспроизводимость задаётся версией алгоритма, seed и количеством завершённых попыток; одинаковый лимит времени на разных устройствах не гарантирует одинаковый результат.

# Просмотр и ручные правки

3D содержит полупрозрачный кузов, размеры, задний проём, номера коробок и цвета остановок. Есть виды сверху, сзади и сбоку, вращение и масштабирование; по нажатию — свойства коробки. Цвет дополнен номером, чтобы не быть единственным обозначением.

Ручное перемещение выполняется в выбранной горизонтальной плоскости или на допустимой опоре; высота выбирается из доступных поверхностей. Есть кнопки поворота, числовой ввод позиции, отмена и повтор. На телефоне предусмотрены крупные элементы управления и переключение между движением камеры и коробки: операции не требуют наведения мыши.

Изменение сначала показывается как предпросмотр. Подтвердить можно только положение, прошедшее полную проверку ограничений и последовательности. Перемещение коробки, на которую опирается другой груз, блокируется с предложением сначала переместить верхние; это относится и к частичной опоре на несколько коробок. Автоматическое движение всей стопки в P0 не требуется. После принятой правки инструкции пересоздаются, шаг выполнения сбрасывается.

Изменение исходных грузов, кузова или ограничений помечает прежний результат устаревшим. Устаревшую схему можно посмотреть с маркировкой, но нельзя выдать за актуальный план. Новый результат привязан к ревизии входных данных; ответ старого worker не заменяет новый проект.

# Сохранение и обмен

Проекты автоматически сохраняются на устройстве в IndexedDB. Сохраняются входные данные, версия схемы, ревизия, проверенный результат, seed/версия решателя и прогресс инструкции. Предусмотрены миграции формата, резервный экспорт JSON и восстановление из него. Очистка данных браузера удаляет локальные проекты, поэтому файл проекта нужен как независимая копия. [Ограничения браузерного хранилища](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

PDF содержит машину, параметры расчёта, состав груза, неразмещённые позиции, обзорные изображения и список последовательности. Пошаговые изображения добавляются опционально, по несколько на страницу. Используется встроенный шрифт с кириллицей и лицензией на распространение. PDF строится из зафиксированной проверенной ревизии; текст остаётся текстом, а 3D-виды — изображениями.

Ссылка — неизменяемый снимок выбранной проверенной раскладки, доступный для просмотра любому обладателю ссылки. Отправка на сервер происходит только по действию «Создать ссылку», с видимым пояснением доступа. Получатель может скопировать снимок в свой локальный проект, но не изменяет оригинал.

Минимальный сервер обмена хранит снимки до 30 дней, ограничивает размер одного снимка 1 МиБ и частоту публикаций. Ссылка содержит криптографически случайный токен не менее 192 бит. Отдельный секрет удаления хранится только у автора; на сервере хранится его хеш. Автор может удалить снимок раньше срока. Редактирование локального проекта не обновляет опубликованную ссылку. Экспорт проекта не включает секреты удаления.

Сервер проверяет схему и лимиты, а получатель заново проверяет план общим валидатором перед показом статуса готовности. Устаревшие или неподдерживаемые версии открываются с объяснением; их нельзя молча трактовать новой семантикой. Снимки не индексируются; нет общедоступного списка. Токены и содержимое грузов не пишутся в журналы. Ошибка сервера не мешает локальному расчёту и экспорту.

Версии пакетов и Node фиксируются при начале реализации в lockfile и файле версии; альфа-релизы не используются.

[SheetJS поддерживает нужные форматы](https://docs.sheetjs.com/docs/miscellany/formats/). Установка — из актуального официального источника с зафиксированной версией и integrity: [публичный npm-пакет xlsx может быть устаревшим](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/). Лицензии зависимостей и шрифта сохраняются в составе проекта.

Разработка локальная на Mac. На этапе реализации проверяется фактическое окружение; его наличие сейчас не предполагается. Docker нужен только как опциональный способ упаковать сервер, не для ежедневной работы. Весь интерфейс и решатель запускаются без API. Для проверки устройства нужен доступный телефону HTTPS-стенд; обычного localhost на Mac недостаточно для проверки установки PWA на телефоне.

Публикация: статическая сборка приложения на HTTPS-хостинге; API и SQLite на одном небольшом сервере с постоянным диском и резервной копией. Конкретный хостинг, домен и платный тариф выбираются перед публикацией; внешняя публикация не входит в текущее поручение составить ТЗ.

# Структура кодовой базы

Один репозиторий с npm workspaces:

- apps/web — PWA, экраны, 3D и worker-обвязка.
- apps/share-api — создание, получение и удаление снимков.
- packages/domain — схемы, версии, единицы, ID и миграции.
- packages/packing — ориентации, кандидаты, эвристика и улучшение.
- packages/validation — геометрия, опора, нагрузки, граф зависимостей и проверка шагов.
- packages/io — импорт, экспорт, шаблон таблицы и сериализация снимков.
- fixtures — эталонные задачи и ожидаемые свойства.
- docs — ТЗ, архитектурные решения, запуск и описание ограничений.

Решатель и валидатор не зависят от React, Three.js, DOM или базы. Они используют одни соглашения о данных, но валидатор самостоятельно пересчитывает ограничения. Координаты сцены преобразуются из предметной модели одним адаптером: миллиметры нельзя незаметно смешать с единицами Three.js.

Основные сущности: Vehicle, CargoType, CargoInstance, ProjectRevision, Placement, Solution, InstructionStep и SharedSnapshot. Placement хранит ID экземпляра, позицию и точную ориентацию. Solution хранит связь с ревизией входных данных, размещённые и отсутствующие ID, статус, метрики, последовательности и сведения о запуске решателя. Результаты проверки не являются доверенными при импорте.

# Телефон и производительность

Целевые браузеры P0: Safari на iPhone и Chrome на Android актуальных поддерживаемых версий на момент выпуска; компьютер — Safari, Chrome и Firefox. Установка и кеширование PWA проверяются отдельно от обычного браузерного запуска. [Документация установки PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Installing).

После первого успешного открытия и подготовки кеша без интернета работают создание проекта, ручной ввод, импорт локального файла, расчёт, 3D, инструкция, сохранение и экспорт. Создание новой ссылки требует сети. Приложение показывает, готово ли оно к офлайн-работе. Обновление Service Worker не перезагружает страницу во время расчёта или заполнения формы.

Цель для проверки производительности: 100 коробок, 20 типов, 5 остановок; предел входа — 300 коробок, 100 типов, 20 остановок. Решатель остаётся эвристикой: даже маленькая задача может не иметь найденного решения за бюджет.

Выбираются и записываются модели одного физического iPhone и одного Android среднего класса, на которых проверяется выпуск. На наборе из 20 заранее зафиксированных задач цель — первый допустимый результат до 5 секунд как минимум в 90% заведомо решаемых случаев; обязательные функциональные примеры должны решаться все. Цель 3D — не менее 30 кадров/с при вращении типовой сцены из 100 коробок. До измерений это критерии приёмки, а не подтверждённые характеристики.

Для 300 коробок предусмотрены сокращение числа подписей, ограничение pixel ratio, отсутствие тяжёлых теней и объединение геометрии. Расчёт можно прервать, интерфейс остаётся управляемым. При уходе приложения в фон расчёт может приостановиться; продолжение в фоне и при выключенном экране не обещается. Последний проверенный результат и ввод сохраняются.

# Приёмка

1. На телефоне можно создать проект, импортировать Excel, выбрать грани, посчитать, вручную поправить, пройти инструкцию и экспортировать результат.
2. Два одинаковых по размерам экземпляра с разными разрешёнными физическими гранями не теряют различие при расчёте и отображении.
3. Коробка с лимитом 0 кг не имеет верхних коробок. В стопке из трёх и более уровней нижние коробки учитывают весь передаваемый вес.
4. Нельзя принять коробки с пересечением, выходом за кузов, недопустимой ориентацией, нарушением модели опоры support-v1 или превышением массы.
5. В сценарии трёх остановок выгружаются только предметы текущей остановки; пути свободны и оставшиеся коробки не теряют опору на каждом шаге.
6. Ни один отсутствующий обязательный экземпляр не скрыт в готовом плане. Известная невозможность, неудача поиска и отмена различимы.
7. Каждая анимация соответствует проверенному пути; загрузка не появляется как простое возникновение коробки внутри кузова.
8. Ошибочная ручная правка отклоняется с объяснением. Изменение вводных инвалидирует старую инструкцию; запоздалый worker не перезаписывает новый результат.
9. Импорт правильно обрабатывает единицы, десятичную запятую, листы, отсутствующие поля и формулы; исходный проект не портится при отмене.
10. Файл проекта сохраняет экземпляры и ориентации при повторном открытии. PDF читается на телефоне и содержит корректную кириллицу.
11. Полный локальный сценарий работает офлайн после подготовки кеша. Перезапуск восстанавливает проект и шаг действующей инструкции.
12. Ссылка содержит именно опубликованную ревизию; истечение срока и удаление понятны получателю. Вредоносный или повреждённый снимок не становится готовой инструкцией.
13. Автоматические проверки включают модульные примеры, генерацию случайных задач с проверкой инвариантов и сквозные сценарии в Chromium/WebKit. Эмуляция мобильного экрана дополняется реальными iPhone и Android.
14. Эталонные задачи включают коробку ровно по доступному размеру, запрещённый переворот, несколько маленьких коробок на одной большой, одну большую на нескольких маленьких, границы допусков покрытия и щели, разные высоты опор, запрет нагрузки 0 кг, разделение и последующее объединение нагрузки без двойного подсчёта, перегруз нижнего уровня, блокировку ранней выгрузки, отсутствие обязательного груза и отмену расчёта.

# Зафиксированные решения

1. Стек React/TypeScript/Three.js и локальный решатель; маленький Node/SQLite-сервис только для обмена.
2. Одна или несколько опор на общей высоте; почти полное покрытие дна, только узкие технологические щели, без внешних свесов; распределение нагрузки по площади контакта.
3. Задняя загрузка через полное сечение заданного полезного прямоугольника; только прямые пути и повороты на 90 градусов.
4. По умолчанию все грузы обязательны, все грани разрешены, масса сверху без ограничения; массы самих грузов обязательны.
5. После обязательных грузов максимизируется объём необязательных; стартовые зазоры 10 мм по границам и 5 мм между коробками по горизонтали.
6. Локальное хранение без аккаунтов, файл резервной копии и публикуемые на 30 дней неизменяемые ссылки.
7. Рабочая цель 100 коробок, предел P0 300; производительность подтверждается на физических телефонах.
